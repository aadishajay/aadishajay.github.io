Cloud Compute to Cloud Database Connectivity in Oracle Cloud Infrastructure

Published on Apr 07, 2022

Filling in the missing parts which I struggled to find.

Connecting to on-prem databases is what I was used to for most of my career. Slowly when the cloud-phase of career came up , connecting to a the cloud database was also not a tough task. But , suddenly it occurred that I had to connect a cloud VM to a Cloud Database and I was failing constantly.

After couple of days , thinking of the trouble itself makes me smile , yes of course with a self pity. :) . But ultimately it turned out to be good learning.

The Challenge

My requirement was to use Oracle Cloud VM as an access gateway that runs only shell-script or python and should connect to an Autonomous Transaction Database in Oracle Cloud. Though it sounds straight forward , getting it done was quite troublesome with either the documentation or the blogs would be mentioning most details but missing a few and ultimately you losing the way. So the challenge was actually finding out which one to follow.

Setting up the basics

Setting up the VM and ATP Database is quite straight forward and well documented. You may set up the SSH access to the VM . You will have to generate the instance wallet for the ATP. Download the wallet as we would require this later.

Downloading the Wallet

mTLS wallet is a zip file which bundles multiple files. These files can be used for establishing connection to the specific database through various clients , eg. SQL_Plus , Python , JDBC , etc. Since , I am using SQL_Plus I am interested in majorly two files in the bundle — sqlnet.ora and tnsnames.ora. You may check if all is well with your DB connection using the wallet in your local SQL Developer. Check the steps here.

Setting up the Oracle Instant Client and SQL Plus in the VM

As mentioned earlier my aim is to connect to the ATP Database from my Oracle Compute instance. We would need to set up Oracle Client and SQL*Plus in the Linux VM. The steps are mentioned elaborately here. But there are a few extra steps required in the end.

Step 1: Download the Basic Package (ZIP) by using the following command:

wget https://download.oracle.com/otn_software/linux/instantclient/214000/instantclient-basic-linux.x64-21.4.0.0.0dbru.zip

Step 2: Download the SQL*Plus Package (ZIP) by using the following command:

wget https://download.oracle.com/otn_software/linux/instantclient/214000/instantclient-sqlplus-linux.x64-21.4.0.0.0dbru.zip

Step 3: Make a new directory for the instant client.

sudo mkdir -p /opt/oracle

Step 4: Unzip the Basic Package in the newly-created directory.

sudo unzip -d /opt/oracle instantclient-basic-linux.x64-21.4.0.0.0dbru.zip

Step 5: Unzip the SQL *Plus Package in the newly-created directory.

sudo unzip -d /opt/oracle instantclient-sqlplus-linux.x64–21.4.0.0.0dbru.zip

Step 7: Set the LD_LIBRARY_PATH in your ~/.bashrc source file. Open the file in vi and add these lines to the end of it export LD_LIBRARY_PATH=/opt/oracle/instantclient_21_4:$LD_LIBRARY_PATH

Step 8: Set the ORACLE_HOME vars in your ~/.bashrc

export ORACLE_HOME=/opt/oracle/instantclient_21_4

Step 9: Set the ORACLE_HOME in your ~/.bashrc

export ORACLE_HOME=/opt/oracle/instantclient_21_4

Step 10: Set the PATH env vars in your ~/.bashrc

export PATH=ORACLE_HOME:LD_LIBRARY_PATH:$PATH

Step 11: Run sqlplus -V command to confirm it’s installed or not.

sqlplus -V

Step 11 should give you no errors.

But we aren’t done yet. We now need to use the mTLS wallet which we have downloaded earlier for connecting to the DB.

Using the wallet (mTLS) for connecting to the database

I found Lucas Jellema‘s blog to be very helpful here. He has explained how to connect the cloud shell to a cloud database instance. For me the case had a little difference , I needed to do the same in a compute instance.

Step 1: Upload the wallet zip file to the compute instance: As I had already uploaded my ssh public key to the VM , I was able to use the scp command to do this. scp ~/Downloads/Wallet_labd.zip opc@:

Step 2: Create a directory db and extract the contents of the zip-file into this directory:

unzip wallet.zip -d db

Step 3: Open sqlnet.ora in the vi editor and set the DIRECTORY to refer to the current directory — that holds the tnsnames.ora file. Save the sqlnet.ora file.

WALLET_LOCATION = (SOURCE = (METHOD = file) (METHOD_DATA = (DIRECTORY="/home/opc/db"))) SSL_SERVER_DN_MATCH=yes

Step 4: Set the TNS_ADMIN vars in your ~/.bashrc

export TNS_ADMIN=/home/opc/db

Step 5: Source your ~/.bashrc file

source ~/.bashrc

Step 6: Test Your DB Connection from SQL*Plus

sqlplus admin@<TNS Name>

Key Takeaways

The key is in setting up the 3 env variables viz. LD_LIBRARY_PATH , ORACLE_HOME , TNS_ADMIN.

  • LD_LIBRARY_PATH : is used to tell dynamic link loader, a small program that begins all your applications, to determine where to look for dynamic shared libraries that an application was linked with. A colon (:) separates a list of directories, and this list is checked even before built-in search path/paths and conventional locations like (/lib, /usr/lib…).
  • ORACLE_HOME environment variable points to the directory where the Oracle database client software is installed.
  • TNS_ADMIN is an environment variable that points to the directory where the SQL*Net configuration files (like sqlnet. ora and tnsnames. ora) are located.
