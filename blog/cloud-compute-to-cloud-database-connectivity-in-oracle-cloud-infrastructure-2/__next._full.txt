1d:T1a05,<p>Connecting to on-prem databases is what I was used to for most of my career. Slowly when the cloud-phase of career came up , connecting to a the cloud database was also not a tough task. But , suddenly it occurred that I had to connect a cloud VM to a Cloud Database and I was failing constantly.</p>
<p>After couple of days , thinking of the trouble itself makes me smile , yes of course with a self pity. :) . But ultimately it turned out to be good learning.</p>
<h2>The <strong>Challenge</strong></h2>
<p>My requirement was to use Oracle Cloud VM as an access gateway that runs only shell-script or python and should connect to an Autonomous Transaction Database in Oracle Cloud.
Though it sounds straight forward , getting it done was quite troublesome with either the documentation or the blogs would be mentioning most details but missing a few and ultimately you losing the way.
So the challenge was actually finding out which one to follow.</p>
<h2>Setting up the basics</h2>
<p>Setting up the VM and ATP Database is quite straight forward and well documented. You may set up the SSH access to the VM . You will have to generate the instance wallet for the ATP. Download the wallet as we would require this later.</p>
<h2>Downloading the Wallet</h2>
<p>mTLS wallet is a zip file which bundles multiple files. These files can be used for establishing connection to the specific database through various clients , eg. SQL_Plus , Python , JDBC , etc. Since , I am using SQL_Plus I am interested in majorly two files in the bundle — sqlnet.ora and tnsnames.ora.
You may check if all is well with your DB connection using the wallet in your local SQL Developer. Check the steps <a href="https://docs.oracle.com/en/cloud/paas/autonomous-data-warehouse-cloud/cswgs/autonomous-connect-sql-developer.html">here</a>.</p>
<h2>Setting up the Oracle Instant Client and SQL Plus in the VM</h2>
<p>As mentioned earlier my aim is to connect to the ATP Database from my Oracle Compute instance. We would need to set up Oracle Client and SQL*Plus in the Linux VM.
The steps are mentioned elaborately <a href="https://www.geeksforgeeks.org/how-to-install-sqlplus-on-linux/">here</a>. But there are a few extra steps required in the end.</p>
<p><strong>Step 1:</strong> Download the Basic Package (ZIP) by using the following command:</p>
<p><code>wget https://download.oracle.com/otn_software/linux/instantclient/214000/instantclient-basic-linux.x64-21.4.0.0.0dbru.zip</code></p>
<p><strong>Step 2:</strong> Download the SQL*Plus Package (ZIP) by using the following command:</p>
<p><code>wget https://download.oracle.com/otn_software/linux/instantclient/214000/instantclient-sqlplus-linux.x64-21.4.0.0.0dbru.zip</code></p>
<p><strong>Step 3:</strong> Make a new directory for the instant client.</p>
<p><code>sudo mkdir -p /opt/oracle</code></p>
<p><strong>Step 4:</strong> Unzip the Basic Package in the newly-created directory.</p>
<p><em><code>sudo unzip -d /opt/oracle instantclient-basic-linux.x64-21.4.0.0.0dbru.zip</code></em></p>
<p><strong>Step 5:</strong> Unzip the SQL *Plus Package in the newly-created directory.</p>
<p><code>sudo unzip -d /opt/oracle instantclient-sqlplus-linux.x64–21.4.0.0.0dbru.zip</code></p>
<p><strong>Step 7:</strong> Set the LD_LIBRARY_PATH in your ~/.bashrc source file.
Open the file in vi and add these lines to the end of it
<code>export LD_LIBRARY_PATH=/opt/oracle/instantclient_21_4:$LD_LIBRARY_PATH</code></p>
<p><strong>Step 8:</strong> Set the ORACLE_HOME vars in your ~/.bashrc</p>
<p><code>export ORACLE_HOME=/opt/oracle/instantclient_21_4</code></p>
<p><strong>Step 9:</strong> Set the ORACLE_HOME in your ~/.bashrc</p>
<p><code>export ORACLE_HOME=/opt/oracle/instantclient_21_4</code></p>
<p><strong>Step 10:</strong> Set the PATH env vars in your ~/.bashrc</p>
<p><code>export PATH=ORACLE_HOME:LD_LIBRARY_PATH:$PATH</code></p>
<p><strong>Step 11:</strong> Run sqlplus -V command to confirm it’s installed or not.</p>
<p><code>sqlplus -V</code></p>
<p>Step 11 should give you no errors.</p>
<p>But we aren’t done yet. We now need to use the mTLS wallet which we have downloaded earlier for connecting to the DB.</p>
<h2><strong>Using the wallet (mTLS) for connecting to the database</strong></h2>
<p>I found <a href="https://medium.com/u/4ac8c86cd8df?source=post_page-----77f58562a2b3--------------------------------">Lucas Jellema</a>‘s <a href="https://technology.amis.nl/oracle-cloud/connecting-sqlplus-in-cloud-shell-to-an-autonomous-database/">blog</a> to be very helpful here. He has explained how to connect the cloud shell to a cloud database instance. For me the case had a little difference , I needed to do the same in a compute instance.</p>
<p><strong>Step 1:</strong> Upload the wallet zip file to the compute instance:
<em>As I had already uploaded my ssh public key to the VM , I was able to use the scp command to do this.</em>
<code>scp ~/Downloads/Wallet_labd.zip opc@:</code></p>
<p><strong>Step 2:</strong> Create a directory <em>db</em> and extract the contents of the zip-file into this directory:</p>
<p><code>unzip wallet.zip -d db</code></p>
<p><strong>Step 3:</strong> Open sqlnet.ora in the vi editor and set the DIRECTORY to refer to the current directory — that holds the tnsnames.ora file. Save the sqlnet.ora file.</p>
<p><code>WALLET_LOCATION = (SOURCE = (METHOD = file) (METHOD_DATA = (DIRECTORY="/home/opc/db")))</code>
<code>SSL_SERVER_DN_MATCH=yes</code></p>
<p><strong>Step 4:</strong> Set the TNS_ADMIN vars in your ~/.bashrc</p>
<p><code>export TNS_ADMIN=/home/opc/db</code></p>
<p><strong>Step 5:</strong> Source your ~/.bashrc file</p>
<p><code>source ~/.bashrc</code></p>
<p><strong>Step 6:</strong> Test Your DB Connection from SQL*Plus</p>
<p><code>sqlplus admin@&#x3C;TNS Name></code></p>
<h2>Key Takeaways</h2>
<p>The key is in setting up the 3 env variables viz. LD_LIBRARY_PATH , ORACLE_HOME , TNS_ADMIN.</p>
<ul>
<li><strong>LD_LIBRARY_PATH :</strong> is used to tell dynamic link loader, a small program that begins all your applications, to determine where to look for dynamic shared libraries that an application was linked with. A colon (:) separates a list of directories, and this list is checked even before built-in search path/paths and conventional locations like (/lib, /usr/lib…).</li>
<li><strong>ORACLE_HOME</strong> environment variable points to the directory where the Oracle database client software is installed.</li>
<li><strong>TNS_ADMIN</strong> is an environment variable that points to the directory where the SQL*Net configuration files (like sqlnet. ora and tnsnames. ora) are located.</li>
</ul>
